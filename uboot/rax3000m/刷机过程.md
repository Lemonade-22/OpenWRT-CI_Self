# RAX3000M（NAND）刷机过程记录

记录一次完整流程：备份 → 进 U-Boot → 刷 BL2 / FIP → 刷固件 → 验证。设备为 CMCC RAX3000M（MT7981B，128 MiB SPI-NAND）。

## 0. 前置

- USB-TTL 转换板，**3.3V 电平**（CH340 可用，FT232RL 更稳）
- 接线：`TX→板 RX`、`RX→板 TX`、`GND→GND`，**VCC 不接**
- 串口参数：`115200 8N1`，无流控
- TFTP 服务端（电脑）与 PuTTY
- 网线：路由器 LAN 口 ↔ 电脑

> 判断 TTL 是否真的连上：发一个回车。若是"回声"（发什么回什么、没有提示符），就是 TX/RX 短接或没接到板子。

## 1. 备份（先做，不要跳）

在系统 root shell 里执行：

```bash
cat /proc/mtd            # 先看清分区名和大小
```

典型布局：

| dev | 大小 | 名称 |
|---|---|---|
| mtd0 | 0x07200000 | ubi |
| mtd1 | 0x00200000 | fip |
| mtd2 | 0x00200000 | factory |
| mtd3 | 0x00080000 | u-boot-env |
| mtd4 | 0x00100000 | bl2 |

逐个备份：

```bash
dd if=/dev/mtd0 of=/tmp/mtd0_ubi.bin
dd if=/dev/mtd1 of=/tmp/mtd1_fip.bin
dd if=/dev/mtd2 of=/tmp/mtd2_factory.bin
dd if=/dev/mtd3 of=/tmp/mtd3_env.bin
dd if=/dev/mtd4 of=/tmp/mtd4_bl2.bin
sha256sum /tmp/mtd*.bin
```

取回电脑：`scp`／WinSCP，或用 U-Boot 的 `/backup.html`。

**优先级**：

1. `factory`（2 MiB）—— MAC 地址 + 无线校准数据，**丢了无线起不来**，无法从任何固件恢复
2. `fip`、`bl2` —— 引导本身
3. `u-boot-env` —— 环境变量
4. `ubi` —— 系统本体，可用固件重刷，备不备看心情

## 2. 进入 U-Boot

### 方式 A：进 Web failsafe（U-Boot 正常时）

1. 断电
2. **按住 RESET 不放**
3. 上电，**数到 5 秒**再松手
4. 电脑保持 DHCP 自动获取，会自动拿到 `192.168.1.x`
5. 浏览器打开 `http://192.168.1.1`

### 方式 B：BROM 救援（U-Boot 已损坏、串口只有 BL2 报错时）

工具：`mtk_uartboot`（见参考网址）。原理是 MTK BootROM 支持串口下载，可以在 flash 里的引导全废时把临时 U-Boot 塞进内存。

```bash
# 先让工具进入等待 Handshake 状态，然后再给板子上电
mtk_uartboot.exe -s COM3 -p mt7981-ddr4-bl2-ram-boot.bin -a -f fip-debrick-only.bin
```

上电时**按住 RESET**，工具才会握上手。

> 波特率：`--brom-load-baudrate 115200 --bl2-load-baudrate 115200` 在部分芯片上会卡在 `Baudrate set to: 115200` 不动。用默认的 460800 / 921600 反而是能跑通的那一档。

## 3. 刷 U-Boot FIP

### 网页方式（推荐）

`/uboot.html` → 选择 FIP 文件 → Upload → Update。设备会自行重启。

### 串口 + TFTP

```
setenv ipaddr 192.168.1.100
setenv serverip 192.168.1.11
tftpboot 0x46000000 fip.bin
```

**先确认传输结果**，必须出现：

```
Bytes transferred = 914640 (df4d0 hex)
```

确认后再写：

```
mtd erase fip
mtd write fip 0x46000000 0 0xdf4d0
mtd read fip 0x50000000 0 0xdf4d0
cmp.b 0x46000000 0x50000000 0xdf4d0
```

必须回显 `Total of 914640 byte(s) were the same`。

## 4. 刷 BL2（仅在需要时）

能正常引导就不要动 BL2。若要一并更换：

```
tftpboot 0x46000000 bl2.img
mtd erase bl2
mtd write bl2 0x46000000 0 0x271ec
cmp.b 0x46000000 0x50000000 0x271ec
```

**顺序：先 BL2，后 FIP。** 反过来一旦中途出错，BL2 与 FIP 不配套会直接起不来。

## 5. 刷固件

### 网页方式

`/` → 选择 sysupgrade 的 `.itb` → Upload → Update。写入完成后自动重启。

### 串口 + TFTP

```
setenv bootfile_upg sysupgrade.itb
setenv replacevol 1
run boot_tftp_production
```

成功时会看到：

```
Creating dynamic volume fit of size 25166092
25166092 bytes written to volume fit
```

## 6. 验证

```bash
cat /proc/mtd                 # ubi 应为 07200000（114 MiB）
ubinfo | grep -i peb          # 912
ip -br link show eth0         # MAC 为原机地址，不是随机
iwinfo                        # WIFI-YES 固件应有无线
sha256sum /dev/mtd2           # 与备份的 factory 一致
```

## 7. 踩过的坑

1. **只换 FIP 不换 BL2**：BL2 报 `io_dev_init failed for FIP image id 0 (-2)` / `Failed to load image id 3`，板子停在 BL2。
2. **布局不匹配**：UBI 按 122 MiB 建、固件按 114 MiB 挂，报 `not enough PEBs, required 958, available 912`，内核永远停在 `Waiting for root device /dev/fit0`。根因是 U-Boot 默认环境里 ubi 尺寸写成 `-(ubi)`（剩余全部），必须写成 `114M(ubi)`。
3. **在 Linux 里往 UBI 卷写数据**：若该布局把 `fip` 分区圈进 UBI 范围，写卷会覆盖 FIP，重启后 BL2 直接挂。恢复 factory 数据应走 U-Boot 的 `mtd write factory`，不要用 `ubiupdatevol`。
4. **TFTP 没核对就写**：传输失败但直接执行 `mtd erase` + `mtd write`，会把内存里的垃圾写进分区。**永远先看 `Bytes transferred`。**
5. **命令行被抢**：U-Boot 菜单倒计时期间发送的命令会被菜单吃掉（比如误选到 `Upgrade ATF FIP`）。要么先稳稳停在 `MT7981>` 提示符，要么用菜单项本身。
